# 项目历史与决策沿革

> 本文记录本项目从零到现在**只在对话里存在、代码里看不出来**的约定与决定。
> 需求原文见 [history-archive.md](./history-archive.md)（自动归档，含时间戳）。
> 接手本项目时，**先读本文，再读代码**。

## 一、项目从哪来

用户给了三样东西，然后要求按技能文档实现：

1. **一份技能文档** [`bazi-chart-calculator.skill.md`](./bazi-chart-calculator.skill.md)
   —— 规定了六十甲子编码、太阳黄经定节气、儒略日定日柱、真太阳时定时柱等数学模型；
2. **技术栈约束**：Vue3 组合式 API + `<script setup lang="ts">`、TypeScript 禁 `any`、
   Vite、Pinia、Vue Router（如有多页）、Vitest，日期处理用 dayjs，
   天文计算不引重型依赖（节气/黄经先用简化公式，标注 TODO 可替换 skyfield/ephem）；
3. **目录结构约定**：`src/core/` 放纯函数（无 Vue 依赖、可单测），组件里禁止写算法。

另外指定了两条**必须通过**的校验用例（见下节「硬校验」）。

## 二、已锁定的设计决策

### 2.1 校验口径（不可随意改动）

| 用例                             | 期望四柱            | 出处                      |
| -------------------------------- | ------------------- | ------------------------- |
| 2008-07-16 10:33 男              | 戊子 己未 丁巳 乙巳 | 用户点名要求              |
| 2000-01-01 00:00 男              | 己卯 丙子 戊午 壬子 | 用户点名要求              |
| 2006-02-27 09:20 男 · 广西天等县 | 丙戌 庚寅 丁亥 甲辰 | 用户报告 bug 时给出的对照 |

技能文档 §6 的**后两例日柱经核实为文档笔误**（1984-02-04 应 戊辰而非丁丑；
2024-02-04 应 戊戌而非己亥，年柱月柱均与文档一致，仅日柱差一位）。
处理方式：不硬编码错值，在测试里并列记录「文档值 vs 计算值」留痕。

### 2.2 时间口径（三轮才定稿，务必别改回去）

```
平太阳时 = 民用钟表时（北京时间，东经 120° 标准时）        ← 不做任何修正
真太阳时 = 平太阳时 + 经度时差 + 均时差
          经度时差 = (lon − 120°) × 4 分钟
          均时差 EoT 按「出生地平太阳时」求值（不是同一瞬间的 UT）
```

演变过程（**踩过的两个坑**）：

1. 第一版按技能 §3.1 实现，含经度项 —— 正确；
2. 用户说「平太阳时就是北京时间」，我误解为**经度时差应剔除**，于是真太阳时只剩 EoT。
   后果：天等县（107.14°E）真太阳时算成 09:07（应 08:16），时柱从 **甲辰** 错成 **乙巳**。
3. 用户报告后修正：**经度时差是「钟表时 → 地方时」的必要换算，不能省**。

> 记牢：三个时钟并列给出（`standardHour` / `trueSolarHour`），
> **计时口径只影响时柱**；日柱取民用日、年月柱取出生瞬间的黄经与节气，与口径无关。

### 2.3 出生地：三级级联 + 插件式数据

- 用户要求：**选择**地址而非手输，精确到县，结构 `省 / 市 / 区县`。
- 数据源：阿里云 DataV 公开行政区划，由 `doc/gen_regions.py` 生成 `core/regions.ts`
  （**34 省级 / 411 市 / 2792 区县**，脚本自带对账与坐标校验）。
- `doc/.region-cache/` 是该脚本的**下载缓存**（约 3600 个 GeoJSON，28 MB），可再生，已 gitignore。

### 2.5 神煞映射表（用户直接给定的规则）

用户在报告「神煞面板显示固定数据」时，给出了一张**逐柱期望表**（以 丙戌 庚寅 丁亥 甲辰 为例）：

| 柱     | 应显示的神煞                                   |
| ------ | ---------------------------------------------- |
| 年干丙 | 月德贵人、天罗                                 |
| 月干庚 | 国印贵人、亡神                                 |
| 日干丁 | 天德贵人、天乙贵人、劫煞、孤辰、十恶大败、天罗 |
| 时干甲 | 童子煞、地网                                   |

实现方式：**先反推起法再让程序算**（不是硬编码这 12 个名字）——
月德/天德由月支定、劫煞/亡神/驿马/桃花以年支与日支为源、孤辰以年支为源、
天罗地网见戌亥/辰巳、十恶大败看日柱干支、童子煞看季节×天干。
共收录二十余类，定位规则见 [算法说明书 §13.2](./bazi-algorithm.md#132-按柱神煞coreshenshamorets)。

> **门派差异**：国印贵人的「庚 → 未」与本项目用例一致（通行口诀另有「庚见丑」说）；
> 孤辰寡宿、童子煞各家亦不统一。差异集中在 `shenshaMore.ts` 顶部常量表，改表即可换门派。

### 2.6 五行计数（用户报告的 bug）

原始实现**只统计四柱天干、漏掉地支**，导致 `丙戌 庚寅 丁亥 甲辰` 显示 0 土 0 水
（实际 土 2、水 1），而界面标题写着「天干 + 地支本气」——标签承诺了、实现没做。
现在两种口径并存：本气（合计 8）与含藏干（合计 > 8），数据源统一为 `constants.ts`。

## 四、如何在别的机器/会话里恢复上下文

```sh
# 1. 克隆代码（含全部文档与历史）
git clone https://github.com/yunzheyue-star/BaZi.git ~/BaZi

# 2. 装依赖并自检
cd ~/BaZi && npm install
bash doc/wsl-verify.sh        # 环境体检 + type-check + 测试 + 构建

# 3. 读顺序：本文 → history-archive.md → 算法说明书 → 代码
```

若要把**原始会话记录**也带走（不止归档文本），拷贝这个目录：

```
~/.dsh/sessions/--C-demo-BaZi--/<session-id>/session.v4.jsonl.zstd
```

它是「多个 zstd 帧顺序拼接」的格式（每帧一条 JSON 记录）。重新导出归档：

```sh
node doc/history-export.mjs                    # 自动搜索 ~/.dsh 下的会话文件
node doc/history-export.mjs <指定的 .zstd 路径>
```

脚本内含格式踩坑注释：`zstdDecompressSync` 只解首帧、流式解压器会在帧边界报
`prefix_unknown`，必须逐帧二分定位边界；且判据是「输出长度等于首帧长度」而非「能解码」
（zstd 会忽略尾部多余字节）。
